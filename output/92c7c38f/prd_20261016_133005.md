# 统一认证服务（Auth Service） - 产品需求文档 (PRD)

## 1. 产品定位
一个以独立服务形式对外提供能力的统一用户认证平台，面向需要快速接入认证能力的前后端开发团队。系统以邮箱 + 密码为唯一认证方式，基于无状态 JWT 实现令牌认证，密码采用加盐哈希（bcrypt/Argon2）存储，并通过无状态服务 + Redis 缓存 + 限流 + 水平扩展满足高并发场景下的性能与稳定性要求，最终以标准化 RESTful API 对外提供注册、登录、登出、令牌刷新与密码重置等完整能力。

## 2. 用户故事

- 作为 **普通用户**，我希望 使用邮箱和密码注册账号，以便 能够快速创建属于自己的账号并开始使用平台

- 作为 **普通用户**，我希望 使用邮箱和密码登录并获取访问令牌，以便 能够安全地访问受保护的功能与资源

- 作为 **普通用户**，我希望 在忘记密码时通过邮箱接收重置链接/验证码并设置新密码，以便 能够自助找回账号访问权限，无需人工介入

- 作为 **普通用户**，我希望 在登录状态下主动登出，以便 能够在公共设备上保护自己的账号安全

- 作为 **普通用户**，我希望 在访问令牌过期时使用刷新令牌获取新的访问令牌，以便 无需重复输入密码即可保持登录状态

- 作为 **前后端开发团队**，我希望 通过标准化 RESTful API 接入认证能力，以便 无需自研认证系统即可快速为自有应用提供统一登录

- 作为 **前后端开发团队**，我希望 使用令牌校验中间件保护业务接口，以便 能够以低侵入方式实现接口鉴权

- 作为 **运维/安全人员**，我希望 配置限流策略并查看认证服务运行指标，以便 能够保障高并发下的服务稳定性并及时发现异常

- 作为 **安全管理员**，我希望 通过令牌黑名单机制吊销已签发的令牌，以便 能够在账号异常时及时阻断风险访问


## 3. 功能模块

### P0 - 邮箱注册
提供用户注册能力，校验邮箱格式与唯一性，创建账号并以加盐哈希方式加密存储密码。


  - 邮箱格式校验

  - 邮箱唯一性校验

  - 密码复杂度校验

  - 密码加盐哈希存储（bcrypt/Argon2）

  - 注册成功返回用户标识



### P0 - 邮箱登录与令牌签发
校验用户凭据，签发 JWT 访问令牌，可选签发刷新令牌。


  - 凭据校验

  - JWT 访问令牌签发

  - 刷新令牌签发（可选）

  - 登录失败计数与锁定

  - 登录成功返回令牌与过期时间



### P0 - JWT 令牌认证中间件
提供令牌校验中间件，保护受保护接口，支持令牌过期校验与刷新。


  - 令牌签名与有效期校验

  - 受保护接口鉴权拦截

  - 令牌刷新接口

  - 令牌黑名单校验（Redis）

  - 鉴权失败统一错误响应



### P0 - 密码加密存储
使用业界标准加盐哈希算法存储密码，禁止明文存储，支持算法参数可配置。


  - bcrypt/Argon2 加盐哈希

  - 哈希算法与强度参数可配置

  - 密码比对安全校验

  - 历史密码策略（可选）



### P1 - 密码重置
通过邮件发送一次性重置链接或验证码，校验后允许用户设置新密码。


  - 重置请求接口

  - 邮件发送重置链接/验证码

  - 重置令牌有效期与一次性校验

  - 设置新密码并更新哈希

  - 重置成功后失效相关令牌



### P0 - RESTful API 接口层
提供注册、登录、登出、令牌刷新、密码重置等标准化 RESTful 接口。


  - 统一接口规范与版本管理

  - 统一请求/响应格式

  - 统一错误码与错误信息

  - 接口文档（OpenAPI/Swagger）



### P1 - 登出与令牌吊销
支持用户主动登出，并通过黑名单机制吊销已签发令牌。


  - 登出接口

  - 访问令牌加入黑名单

  - 刷新令牌吊销

  - 黑名单过期自动清理



### P1 - 高并发支撑能力
通过无状态服务、缓存、连接池、限流与水平扩展保障高并发下的性能与稳定性。


  - 无状态服务设计

  - Redis 缓存与连接池

  - 接口限流与防刷

  - 水平扩展与负载均衡

  - 健康检查与可观测性指标



### P2 - 安全审计与日志
记录关键认证事件，支持安全审计与异常追踪。


  - 登录/注册/重置事件日志

  - 异常登录告警

  - 审计日志留存

  - 敏感信息脱敏




## 4. 用户流程

### 用户注册流程

1. 用户提交邮箱与密码至注册接口

2. 系统校验邮箱格式与唯一性

3. 系统校验密码复杂度

4. 系统对密码进行加盐哈希

5. 系统创建账号并持久化

6. 返回注册成功结果与用户标识


### 用户登录流程

1. 用户提交邮箱与密码至登录接口

2. 系统查询账号并校验凭据

3. 校验失败则记录失败次数并返回错误

4. 校验成功则签发 JWT 访问令牌（可选刷新令牌）

5. 返回令牌与过期时间给客户端


### 受保护接口访问流程

1. 客户端在请求头携带访问令牌

2. 认证中间件解析并校验令牌签名与有效期

3. 校验令牌是否在黑名单中

4. 校验通过则放行并注入用户身份

5. 校验失败则返回 401 未授权


### 令牌刷新流程

1. 客户端携带刷新令牌请求刷新接口

2. 系统校验刷新令牌有效性与是否被吊销

3. 校验通过则签发新的访问令牌

4. 返回新的访问令牌与过期时间


### 密码重置流程

1. 用户提交注册邮箱请求重置密码

2. 系统生成一次性重置令牌并通过邮件发送链接/验证码

3. 用户点击链接或输入验证码

4. 系统校验重置令牌有效性与一次性

5. 用户设置新密码，系统更新密码哈希

6. 系统失效相关令牌并返回成功


### 用户登出流程

1. 用户发起登出请求并携带访问令牌

2. 系统将访问令牌加入黑名单并吊销刷新令牌

3. 返回登出成功结果



## 5. 非功能性需求

- **性能**：认证核心接口（登录、令牌校验）在高并发下保持低延迟，服务无状态可水平扩展（指标：登录/令牌校验接口 P99 延迟 < 200ms；单实例支持 ≥ 5k QPS，集群可线性扩展至 ≥ 50k QPS）

- **安全**：密码必须加盐哈希存储，禁止明文；令牌签名与传输安全；防暴力破解（指标：密码 100% 哈希存储（bcrypt cost ≥ 10 或 Argon2id）；全链路 HTTPS；登录失败 5 次锁定 15 分钟）

- **可用性**：服务具备高可用与故障恢复能力，支持健康检查与自动扩缩容（指标：服务可用性 ≥ 99.9%；单点故障不影响整体服务；支持滚动发布不中断）

- **可扩展性**：无状态设计，支持水平扩展与缓存/连接池优化（指标：新增实例无需共享会话状态；Redis 连接池与数据库连接池可配置）

- **可观测性**：提供关键指标、日志与链路追踪，便于监控与排障（指标：暴露 QPS、延迟、错误率、令牌签发量等指标；关键认证事件全量审计日志）

- **合规与隐私**：遵循数据保护要求，敏感信息脱敏存储与传输（指标：日志中不记录明文密码与完整令牌；支持用户数据删除请求）

- **限流与防刷**：对认证接口实施限流与防刷策略，防止滥用与攻击（指标：按 IP/账号维度限流，超限返回 429；重置邮件发送频率限制）


## 6. 成功指标

- 注册接口成功率 ≥ 99%，注册转化流程无阻塞

- 登录接口 P99 延迟 < 200ms，成功率 ≥ 99.5%

- 令牌校验中间件平均耗时 < 10ms

- 密码重置邮件送达率 ≥ 98%，重置成功率 ≥ 95%

- 服务可用性 ≥ 99.9%，支持 ≥ 50k QPS 峰值

- 安全事件（暴力破解/异常登录）可 100% 被记录与告警

- 接入团队平均集成时间 < 1 人日


## 7. 不在范围内

- 手机号注册/登录

- 第三方登录（OAuth2、微信、Google 等）

- 多因素认证（MFA/2FA）

- 单点登录（SSO）与跨域联邦认证

- 用户资料管理（头像、昵称、个人主页等）

- 权限与角色管理（RBAC/ABAC）

- 短信验证码通道

- 计费与订阅相关功能
